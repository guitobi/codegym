# CodeGym — тренажер читання коду на Rust

Локальна CLI-утиліта, схожа за досвідом на Sphinx, але з фокусом на вивчення реального коду: архітектура фічі, призначення функцій, місця виклику, рух даних, прогноз поведінки та написання коду.

## Встановлення

Потрібні: Rust/Cargo, Git, Codex CLI з авторизацією (codex login status).

У PowerShell:

    cd "D:\programatyvna_shlaypa(sandbox)\codegym"
    cargo test
    cargo install --path .

Бінарник встановлюється у папку %USERPROFILE%\.cargo\bin. Якщо вона є в PATH, можна запускати CodeGym з будь-якого репозиторію.

## Приклади

    cd "D:\appexoft\whimsy\whimsy.platform\whimsy.rfp"
    codegym                         # Навчання на змінах гілки порівняно з main
    codegym feature --base main     # Архітектура, логіка, крайні випадки
    codegym function snapToWeek    # Навчання на визначенні й викликах реальної функції
    codegym graph snapToWeek       # Кандидати на виклики за ім'ям (без AI)
    codegym graph snapToWeek --from "apps/web/src/app/(app)/admin/assignments/_lib/snap-to-week.ts"  # Визначення + звірені відносні імпорти
    codegym inspect --base main    # Які файли потраплять в урок (без AI)
    codegym practice --questions 3  # Самостійно писати код
    codegym review                  # Без підказок
    codegym progress                # Історія балів за темами

Або з будь-якої папки:

    codegym feature --repo "D:\appexoft\whimsy\whimsy.platform\whimsy.rfp"

Додаткові параметри: --base origin/main, --questions 1..5, --model gpt-6-luna.

Після генерації питань бачиш текст справжнього коду з номерами рядків, питання українською і поле відповіді. Відповідь оцінюється через Codex за шкалою 0..5 із поясненням помилок.

Команди під час навчання:
- :source — ще раз показати фрагмент коду;
- :hint — підказка, окрім режиму review;
- :ask чому тут await? — уточнення до AI-викладача за поточним фрагментом коду без завершення питання (додатковий виклик Codex; викладач намагається не розкривати готову відповідь); у режимі review недоступно;
- :learn — розкрити пояснення та отримати 0 балів;
- :skip — пропустити;
- :quit — закінчити сесію;
- .done — завершити багаторядкову відповідь із кодом у practice.

## Як працює

1. Через локальний Git обчислюється merge-base відносно базової гілки; додатково враховуються staged/unstaged зміни.
2. Обирається до 14 Git-відстежуваних вихідних файлів із різних шарів (service, db, API, UI, tests). Для TypeScript/TSX додатково шукаються можливі виклики змінених функцій у **незмінених файлах**, щоб побачити ширшу архітектуру. Пошук обмежений за обсягом і може пропустити зв'язки.
3. Модель отримує обмежені фрагменти загальним обсягом до 40 KB і формує питання, прив'язані до конкретних файлів та рядків.
4. У режимі `function` Tree-sitter аналізує AST TypeScript/TSX і знаходить оголошення, виклики та функції-викликачі; для інших мов використовується текстовий fallback. `graph` показує результати без AI.
5. Відповіді оцінює Codex. Бали, теми та наступний термін повторення зберігаються локально у %LOCALAPPDATA%\codegym\progress.json. Після правильної відповіді тема повертається через 1, 3, 7, 14 або 30 днів; після помилки — раніше.

Git fetch, Git push, Git commit та автоматичні Git hooks НЕ виконуються. Мережевий доступ до GitLab не потрібен. Зміни у проєкті не вносяться.

## RAM, безпека, приватність

- Нативний CLI без сервера, бази даних чи браузера. Окремий процес Codex споживає оперативну пам'ять лише під час генерації та перевірки питань.
- Codex працює із тимчасової папки у read-only sandbox із вимкненими shell tools, MCP, hooks, web search, agent extensions; робочий репозиторій не передається йому як файлове дерево.
- ВАЖЛИВО: вибрані уривки коду надсилаються налаштованому AI-провайдеру через Codex CLI. Перевір внутрішні правила компанії.
- Приховані файли, node_modules, dist, build, target, а також файли зі словами secret/credential виключено; однак секрети можуть бути і в інших Git-файлах. Це НЕ DLP-гарантія.
- Прогрес не містить відповідей чи вихідного коду.
- Немає телеметрії CodeGym або автоматичних оновлень.
- Для TypeScript/TSX Tree-sitter показує оголошення, виклики й функцію-викликач. Без `--from` це лише кандидати за ім'ям. З `--from` враховуються прямі **відносні іменовані імпорти**, зокрема `import { foo as alias }`; виклики однофамільців з інших файлів відкидаються. Це **не повний семантичний type-checker**: `@/`-аліаси, реекспорти, namespace/default imports, затінення та динамічний dispatch поки не розв'язуються. Для інших мов — текстовий пошук.
- У `practice` Codex створює самодостатнє завдання на написання **чистої JavaScript-функції**, а також 3–5 тестових випадків. Користувач вводить весь код функції та завершує `.done`. QuickJS всередині процесу Rust виконує функцію й порівнює виходи з очікуваними результатами. Неуспішні тести обмежують AI-оцінку.
- Тестовий QuickJS не отримує функцій доступу до ОС, диска, мережі або репозиторію. Ліміти: **16 МБ пам'яті, 750 мс CPU/часовий interrupt, 256 КБ стека**. Тести запускають лише код учня, а не код репозиторію. Це окреме середовище JS, **не TypeScript-compiler і не повноцінна ОС-пісочниця**. JavaScript завдання не потребують Node або встановлення npm-пакетів. Генерація/оцінка все ще використовує Codex.
- Паралельно Tree-sitter перевіряє синтаксис введеного коду, коли вихідний файл — TypeScript/TSX; це не `tsc`. Важливо: **тести генерує AI**, тому можливі помилки в еталонних значеннях; їх треба перевіряти.

## Перевірки розробника

    cargo fmt --check
    cargo clippy --all-targets -- -D warnings
    cargo test
    cargo build --release

Проєкт ще не має повного TypeScript LSP, персональних карток конкретних помилок та багатопанельного TUI. Уже є повторення на рівні тем, локальний ізольований запуск JavaScript-кейсів і часткова перевірка відносних імпортів. Наступні покращення: семантичне розв'язання TS-аліасів/реекспортів, повторення конкретних помилок та кращий термінальний інтерфейс.
