# CodeGym — тренажер читання коду на Rust

Локальна CLI-утиліта, схожа за досвідом на Sphinx, але з фокусом на вивчення реального коду: архітектура фічі, призначення функцій, місця виклику, рух даних, прогноз поведінки та написання коду. Термінал показує кольорові заголовки, нумеровані фрагменти коду, позначки прогресу та результати; перенаправлений вивід і `NO_COLOR` працюють без кольорів. Повноекранний TUI на Ratatui доступний через `--tui`; звичайний режим без нього лишається для конвеєрів, малих терміналів та автоматизації.

## Встановлення

Потрібні: Rust/Cargo, Git, Codex CLI з авторизацією (codex login status).

У PowerShell:

    cd "D:\programatyvna_shlaypa(sandbox)\codegym"
    cargo test
    cargo install --path .

Бінарник встановлюється у папку %USERPROFILE%\.cargo\bin. Якщо вона є в PATH, можна запускати CodeGym з будь-якого репозиторію.

## Приклади

    cd "D:\appexoft\whimsy\whimsy.platform\whimsy.rfp"
    codegym                         # Навчання на змінах гілки порівняно з main
    codegym feature --base main     # Архітектура, логіка, крайні випадки
    codegym function snapToWeek    # Навчання на визначенні й викликах реальної функції
    codegym graph snapToWeek       # Кандидати на виклики за ім'ям (без AI)
    codegym graph snapToWeek --from "apps/web/src/app/(app)/admin/assignments/_lib/snap-to-week.ts"  # Визначення + звірені відносні імпорти
    codegym graph snapToWeek --from "apps/web/src/app/(app)/admin/assignments/_lib/snap-to-week.ts" --semantic  # Справжній TypeScript type checker
    codegym function snapToWeek --from "apps/web/src/app/(app)/admin/assignments/_lib/snap-to-week.ts" --semantic  # Навчання із семантичними викликами
    codegym inspect --base main    # Які файли потраплять в наступний урок (без AI)
    codegym inspect --page 2      # Перегляд іншої частини фічі без AI
    codegym practice --questions 3  # Самостійно писати код
    codegym review                  # Без підказок
    codegym feature --fresh         # Скасувати незавершене заняття і почати нове
    codegym progress                # Історія балів за темами
    codegym mistakes                # Повернутись до конкретних питань, де були помилки
    codegym feature --tui           # Повноекранні панелі коду, питання та відповіді

Або з будь-якої папки:

    codegym feature --repo "D:\appexoft\whimsy\whimsy.platform\whimsy.rfp"

Додаткові параметри: --base origin/main, --questions 1..5, --model gpt-6-luna.

Після генерації питань бачиш текст справжнього коду з номерами рядків, питання українською і поле відповіді. Відповідь оцінюється через Codex за шкалою 0..5 із поясненням помилок.

Команди під час навчання:
- :source — ще раз показати фрагмент коду;
- :hint — підказка, окрім режиму review;
- :ask чому тут await? — уточнення до AI-викладача за поточним фрагментом коду без завершення питання (додатковий виклик Codex; викладач намагається не розкривати готову відповідь); у режимі review недоступно;
- :learn — розкрити пояснення та отримати 0 балів;
- :skip — пропустити;
- :quit — призупинити заняття; під час наступного запуску воно відновиться з поточного питання (якщо код не змінився);
- .done — завершити багаторядкову відповідь із кодом у practice.

## Як працює

1. Через локальний Git обчислюється merge-base відносно базової гілки; додатково враховуються staged/unstaged зміни.
2. Обирається до 14 Git-відстежуваних вихідних файлів із різних шарів (service, db, API, UI, tests). **Після успішної генерації уроку** номер сторінки зберігається, наступне заняття переходить до інших змінених файлів (для WPF-20 це три сторінки по ~14 файлів). `codegym inspect` показує наступну сторінку без її витрачання, а `--page N` примусово вибирає сторінку й не змінює чергу. Для TypeScript/TSX додатково шукаються можливі виклики змінених функцій у **незмінених файлах**, щоб побачити ширшу архітектуру. Пошук обмежений за обсягом і може пропустити зв'язки.
3. Модель отримує обмежені фрагменти загальним обсягом до 40 KB і формує питання, прив'язані до конкретних файлів та рядків. **Перед показом запитання** CodeGym перевіряє реальність файлу та номера рядка; вигадані джерела відхиляє, а не підміняє довільним файлом. Одна спроба виправлення AI-відповіді дозволена; після другої невдачі заняття зупиниться з поясненням.
4. У режимі `function` Tree-sitter аналізує AST TypeScript/TSX і знаходить оголошення, виклики та функції-викликачі; для інших мов використовується текстовий fallback. `graph` показує результати без AI.
5. Відповіді оцінює Codex. Бали, теми та наступний термін повторення зберігаються локально у %LOCALAPPDATA%\codegym\progress.json. Після правильної відповіді тема повертається через 1, 3, 7, 14 або 30 днів; після помилки — раніше.
6. Поточна черга запитань зберігається в %LOCALAPPDATA%\codegym\sessions\ та відновлюється після `:quit`/перезапуску без повторного запиту до AI. Якщо змінилася база/гілка/вміст контексту Git, старе заняття вважається неактуальним. `--fresh` дозволяє скасувати незавершений урок. Заняття з ручним `--page N` одноразові й не перезаписують збережений автоматичний урок.

Git fetch, Git push, Git commit та автоматичні Git hooks НЕ виконуються. Мережевий доступ до GitLab не потрібен. Зміни у проєкті не вносяться.

## RAM, безпека, приватність

- Нативний CLI без сервера, бази даних чи браузера. Окремий процес Codex споживає оперативну пам'ять лише під час генерації та перевірки питань.
- Codex працює із тимчасової папки у read-only sandbox із вимкненими shell tools, MCP, hooks, web search, agent extensions; робочий репозиторій не передається йому як файлове дерево.
- ВАЖЛИВО: вибрані уривки коду надсилаються налаштованому AI-провайдеру через Codex CLI. Перевір внутрішні правила компанії.
- Приховані файли, node_modules, dist, build, target, а також файли зі словами secret/credential виключено; однак секрети можуть бути і в інших Git-файлах. Це НЕ DLP-гарантія.
- `%LOCALAPPDATA%\codegym\progress.json` містить статистику **та картки помилок із текстами питань і еталонними відповідями**. Каталог `sessions` зберігає незавершені запитання. Введені відповіді не зберігаються, але AI-еталони можуть містити фрагменти корпоративного коду. Вважай ці локальні файли конфіденційними; вони не потрапляють у Git-репозиторій.
- Немає телеметрії CodeGym або автоматичних оновлень.
- Стандартний Rust/Tree-sitter граф показує оголошення, виклики та функцію-викликач. Без `--from` це кандидати за ім'ям; з `--from` перевіряються прямі відносні іменовані імпорти. Для **точного TypeScript type checker** додай `--from PATH --semantic` до `graph` або `function`. Цей режим за потреби запускає окремий Node з установленим TypeScript (`npm install -g typescript` або `CODEGYM_TYPESCRIPT_PATH`). Він враховує tsconfig `paths`, реекспорти, alias та однойменні символи, але обмежує граф впливу 96 модулями і має 35-секундний ліміт; динамічні виклики, JavaScript reflection і невключені проєктні посилання не гарантуються. Семантичний режим запускається **лише за явним прапорцем** й має ліміт V8 heap 384 МБ (фактична RAM процесу може бути вищою); звичайний CLI/AST використовує значно менше. Для мов, окрім TS/TSX, використовується текстовий fallback.
- У `practice` Codex створює самодостатнє завдання на написання **чистої JavaScript-функції**, а також 3–5 тестових випадків. Користувач вводить весь код функції та завершує `.done`. QuickJS всередині процесу Rust виконує функцію й порівнює виходи з очікуваними результатами. Неуспішні тести обмежують AI-оцінку.
- Тестовий QuickJS не отримує функцій доступу до ОС, диска, мережі або репозиторію. Ліміти: **16 МБ пам'яті, 750 мс CPU/часовий interrupt, 256 КБ стека**. Тести запускають лише код учня, а не код репозиторію. Це окреме середовище JS, **не TypeScript-compiler і не повноцінна ОС-пісочниця**. JavaScript завдання не потребують Node або встановлення npm-пакетів. Генерація/оцінка все ще використовує Codex.
- Для `practice` модель також надає еталонну JavaScript-функцію. **До показу вправи** CodeGym проганяє на ній усі тести: невідповідні завдання повторно генеруються або відхиляються. Це перевіряє внутрішню узгодженість тестів та еталона, проте **не доводить правильності самої постановки задачі**. Паралельно Tree-sitter перевіряє синтаксис введеного коду для TypeScript/TSX; це не `tsc`.

## Перевірки розробника

    cargo fmt --check
    cargo clippy --all-targets -- -D warnings
    cargo test
    cargo build --release

Повноекранний TUI доступний із `--tui` (F1 — підказка, F2 — викладач, F3 — розбір, F4 — пропуск, F5 — перевірка, PgUp/PgDn — код, Esc — вихід). Потрібен інтерактивний термінал; для screen reader та скриптів залишено лінійний CLI. Персональні картки помилок працюють через `codegym mistakes`, а їхню актуальність перевіряють за відбитком вихідного фрагмента. Семантичний TypeScript-аналіз доступний через `--semantic`, але це обмежений дослідженням обраної функції type checker, а не повний IDE/LSP чи безумовна гарантія всіх можливих викликів.
